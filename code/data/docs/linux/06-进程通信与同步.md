# 进程通信与同步

## 1. 为什么需要进程通信

不同进程拥有独立地址空间，默认不能直接共享数据，因此需要进程间通信机制完成信息交换。

常见需求包括：

- 任务协作
- 数据传递
- 事件通知
- 资源共享

## 2. 常见 IPC 机制

Linux 常见进程通信机制包括：

- 管道 pipe
- 命名管道 FIFO
- 消息队列
- 共享内存
- 信号量
- 套接字 socket
- 信号 signal

## 3. 管道

管道适合有亲缘关系的进程通信，特点是：

- 半双工
- 基于字节流
- 通常用于父子进程

## 4. 共享内存

共享内存是一种高效的 IPC 方式，因为数据不需要在进程之间多次复制。

但共享内存本身只解决“共享数据”，不解决“并发安全”，通常要配合同步机制使用。

## 5. 同步与互斥

多线程或多进程访问共享资源时，常见问题包括：

- 竞态条件
- 数据不一致
- 死锁

常见同步机制：

- 互斥锁 mutex
- 读写锁 rwlock
- 条件变量 condition variable
- 信号量 semaphore
- 自旋锁 spinlock

## 6. 自旋锁与互斥锁

### 自旋锁

- 获取不到锁时不会睡眠，而是一直循环等待
- 适合临界区很短、不能睡眠的上下文

### 互斥锁

- 获取不到锁时可以睡眠
- 适合用户态和普通内核线程场景

## 7. 死锁的四个必要条件

常见理论中，死锁成立通常需要以下条件：

1. 互斥
2. 占有且等待
3. 不可剥夺
4. 循环等待

## 8. 常见面试问答

### 问：为什么共享内存速度快？

答：因为多个进程直接访问同一块内存区域，避免了额外的数据拷贝。

### 问：为什么共享内存通常要配合锁？

答：因为多个执行流同时访问共享数据时，会发生竞态，需要同步机制保证一致性。

### 问：什么情况下更适合用 socket 而不是管道？

答：当通信双方没有亲缘关系，或者需要跨主机通信时，socket 更适合。
