# 设备驱动与内核模块

## 1. 设备驱动的作用

设备驱动是内核与硬件之间的桥梁。应用程序通常不直接操作寄存器，而是通过系统调用访问驱动，再由驱动与硬件交互。

驱动的核心职责包括：

- 初始化设备
- 配置寄存器
- 响应中断
- 提供文件操作接口
- 完成数据收发

## 2. 常见设备分类

Linux 中常见设备可以分为：

- 字符设备
- 块设备
- 网络设备

### 字符设备

按字节流方式访问，例如串口。

### 块设备

按块方式访问，例如磁盘、SD 卡。

### 网络设备

以数据包方式收发，例如网卡。

## 3. 字符设备驱动常见接口

字符设备驱动常见操作接口包括：

- `open`
- `read`
- `write`
- `release`
- `ioctl`

这些接口通常通过 `file_operations` 结构体注册。

## 4. 什么是内核模块

内核模块是可以动态加载和卸载的内核代码。

优点：

- 不必把所有驱动都编进内核
- 便于调试和升级
- 有助于裁剪系统体积

常见命令：

```bash
insmod demo.ko
rmmod demo
lsmod
modinfo demo.ko
```

## 5. 驱动加载流程

一个简化的驱动加载流程通常是：

1. 驱动模块被加载
2. 执行模块初始化函数
3. 驱动向内核注册设备或总线驱动
4. 内核根据设备树或总线信息完成匹配
5. 执行 `probe`
6. 设备就绪

## 6. `probe` 与 `remove`

### `probe`

驱动与设备匹配成功时调用，主要完成：

- 申请资源
- 映射寄存器
- 注册中断
- 初始化硬件

### `remove`

设备移除或模块卸载时调用，主要完成资源释放。

## 7. 常见面试问答

### 问：为什么说驱动开发本质上是在“管理资源”？

答：因为驱动需要申请和释放内存、寄存器映射、中断号、DMA 缓冲区、时钟和 GPIO 等资源。

### 问：内核模块和普通用户程序有什么本质区别？

答：内核模块运行在内核态，出错可能直接导致系统崩溃；普通用户程序运行在用户态，隔离性更强。

### 问：为什么不建议在驱动里做大量耗时操作？

答：驱动运行在内核态，尤其在中断上下文中做耗时操作会影响系统实时性和稳定性。
