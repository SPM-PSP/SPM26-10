# 中断、轮询与 I/O 模型

## 1. 什么是中断

中断是硬件或软件通知 CPU 立即处理某个事件的机制。

常见中断来源：

- 外设数据到达
- 定时器到期
- 错误事件
- 软件触发

中断的优点是 CPU 不需要一直忙等，效率更高。

## 2. 中断处理的基本流程

1. 外设发出中断信号
2. CPU 暂停当前任务
3. 保存上下文
4. 跳转到中断处理程序
5. 执行中断服务逻辑
6. 恢复上下文并返回

## 3. 上半部与下半部

Linux 中常把中断处理拆分为：

- 上半部
- 下半部

### 上半部

要求尽快执行，主要完成：

- 读取状态
- 清中断
- 记录必要信息

### 下半部

把较耗时的工作延后处理，常见机制包括：

- softirq
- tasklet
- workqueue

## 4. 轮询

轮询是程序周期性检查设备状态的方式。

优点：

- 实现简单
- 某些实时场景可控

缺点：

- 浪费 CPU
- 延迟和检查周期相关

## 5. 阻塞与非阻塞 I/O

### 阻塞 I/O

当数据未准备好时，调用方会被挂起等待。

### 非阻塞 I/O

当数据未准备好时，调用方立刻返回，不会一直等待。

## 6. `select`、`poll`、`epoll`

### `select`

- 早期多路复用接口
- 支持同时监听多个文件描述符
- 文件描述符数量有限制

### `poll`

- 与 `select` 类似
- 没有固定的位图大小限制

### `epoll`

- 适合大量连接场景
- 避免每次线性扫描所有文件描述符
- 常见于高并发网络服务

## 7. 常见面试问答

### 问：中断和轮询的核心区别是什么？

答：中断由事件主动通知 CPU；轮询由 CPU 主动不断检查状态。

### 问：为什么中断上半部应该尽量短？

答：因为中断处理期间会影响系统对其他任务的响应，过长会拖慢系统整体实时性。

### 问：`select` 和 `poll` 的共同问题是什么？

答：每次调用都需要遍历监听集合，连接数很多时性能会下降。
