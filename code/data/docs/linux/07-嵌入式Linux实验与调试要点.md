# 嵌入式 Linux 实验与调试要点

## 1. 常见调试入口

嵌入式 Linux 开发中常见的调试入口包括：

- 串口日志
- `dmesg`
- `printk`
- `journalctl`
- `gdb`
- `strace`
- `top` / `htop`

其中串口日志通常是最基础也最关键的入口，因为很多启动问题发生在网络和图形界面可用之前。

## 2. `dmesg` 的用途

`dmesg` 用于查看内核日志，常用于定位：

- 驱动加载失败
- 中断注册失败
- 文件系统挂载失败
- 内存分配错误
- 设备树匹配问题

## 3. `printk` 与用户态日志

### `printk`

- 用于内核态日志输出
- 常见于驱动调试

### 用户态日志

- 常见方式包括 `printf`、syslog、日志文件输出
- 适合应用程序调试

## 4. `gdb` 的基本作用

`gdb` 常用于：

- 设置断点
- 单步执行
- 查看变量值
- 分析崩溃现场
- 查看调用栈

对于交叉开发环境，常见方式是：

- 目标板运行 `gdbserver`
- 主机运行交叉 `gdb`

## 5. `strace` 的作用

`strace` 主要用于追踪系统调用，可以帮助定位：

- 文件打开失败
- 设备访问失败
- 权限问题
- 程序卡在哪个系统调用上

## 6. 定位问题的常见思路

### 启动失败

优先看：

- 串口日志
- Bootloader 参数
- 根文件系统是否可挂载
- 设备树是否匹配

### 驱动不工作

优先看：

- 驱动是否加载
- `probe` 是否执行
- 中断是否注册成功
- GPIO / 时钟 / 寄存器是否配置正确

### 应用异常

优先看：

- 用户态日志
- 系统调用返回值
- 文件路径和权限
- 依赖库是否完整

## 7. 实验报告常见考点

在教学或实验场景中，常见考点包括：

- 启动流程理解
- 驱动加载顺序
- 设备树和驱动匹配关系
- 中断与轮询对比
- IPC 机制选择
- 日志与调试方法

## 8. 常见面试问答

### 问：为什么串口日志在嵌入式系统中特别重要？

答：因为很多问题发生在系统早期启动阶段，此时图形界面和网络尚不可用，串口往往是唯一可见输出通道。

### 问：驱动加载成功但设备不能工作，应该先查什么？

答：先确认 `probe` 是否执行、寄存器是否初始化、中断是否正常、设备树资源是否匹配。

### 问：如何区分是内核问题还是应用问题？

答：如果异常发生在驱动初始化、系统调用、设备访问、内核日志层面，更偏内核或驱动问题；如果内核接口正常但业务逻辑出错，更偏应用问题。
