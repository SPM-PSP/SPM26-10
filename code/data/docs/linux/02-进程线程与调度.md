# 进程、线程与调度基础

## 1. 进程的基本概念

进程是正在运行的程序实例，是资源分配的基本单位。每个进程通常拥有：

- 独立的地址空间
- 打开的文件描述符
- 进程 ID
- 运行状态
- 代码段、数据段、堆和栈

Linux 中可以通过 `ps`、`top`、`htop` 等命令观察进程状态。

## 2. 线程的基本概念

线程是 CPU 调度的基本单位。同一进程中的多个线程共享：

- 地址空间
- 全局变量
- 文件描述符

但每个线程有自己的：

- 栈
- 寄存器上下文
- 调度状态

## 3. 进程与线程的区别

### 进程

- 隔离性更强
- 创建和切换成本更高
- 适合独立服务或独立任务

### 线程

- 创建和切换更轻量
- 通信更方便
- 但共享资源更多，更容易出现竞态条件

## 4. 进程状态

Linux 中常见进程状态包括：

- `R`：运行态或就绪态
- `S`：可中断睡眠
- `D`：不可中断睡眠
- `T`：暂停或被跟踪
- `Z`：僵尸进程

### 问：什么是僵尸进程？

答：子进程已经结束，但父进程尚未调用 `wait` 或 `waitpid` 回收其退出状态，导致该进程表项仍然存在。

## 5. 调度的目标

Linux 调度器的主要目标是：

- 让 CPU 使用率更高
- 保证交互响应性
- 保证实时任务及时运行
- 在公平性和吞吐量之间取得平衡

## 6. 上下文切换

上下文切换是指 CPU 从一个任务切换到另一个任务时保存和恢复执行现场的过程。

它通常涉及：

- 保存当前寄存器
- 切换栈
- 切换内存映射
- 恢复下一个任务的上下文

频繁上下文切换会增加系统开销。

## 7. 用户态与内核态

Linux 系统中存在两种典型执行模式：

- 用户态
- 内核态

应用程序大多数时间运行在用户态；执行系统调用、处理中断、访问硬件资源时会进入内核态。

## 8. 常见面试问答

### 问：为什么线程切换通常比进程切换更快？

答：因为同一进程内线程共享地址空间，切换时通常不需要像进程切换那样更换完整的内存映射。

### 问：什么情况下进程会进入 `D` 状态？

答：通常是等待不可中断的 I/O，例如块设备或驱动中的某些等待过程。

### 问：CPU 利用率高是不是一定说明系统运行良好？

答：不一定。如果 CPU 高利用率伴随大量上下文切换、长时间等待或高负载，系统可能仍然性能不佳。
