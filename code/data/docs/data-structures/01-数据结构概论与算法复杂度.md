# 数据结构概论与算法复杂度

## 1. 什么是数据结构

数据结构是相互之间存在一种或多种特定关系的数据元素集合，以及基于这些数据元素集合定义的操作。

简单理解，数据结构主要解决两个问题：

- 数据怎么组织
- 数据怎么高效操作

## 2. 数据结构与算法的关系

数据结构和算法通常是配套出现的。

- 数据结构决定数据的存储组织方式
- 算法决定对这些数据进行处理的步骤

同一个问题，若数据结构设计不同，算法效率也可能差别很大。

## 3. 逻辑结构与存储结构

### 逻辑结构

逻辑结构描述数据元素之间的逻辑关系，常见类型包括：

- 集合结构
- 线性结构
- 树形结构
- 图状结构

### 存储结构

存储结构描述数据在计算机中的实际存放方式，常见类型包括：

- 顺序存储
- 链式存储
- 索引存储
- 散列存储

## 4. 常见抽象数据类型

抽象数据类型强调“逻辑关系 + 操作集合”，而不强调具体实现。

例如：

- 线性表
- 栈
- 队列
- 树
- 图

## 5. 算法的五个基本特性

一个算法通常应具备以下特性：

1. 有穷性
2. 确定性
3. 可行性
4. 输入
5. 输出

## 6. 时间复杂度

时间复杂度用于描述算法执行时间随问题规模增长的变化趋势。

常见复杂度有：

- `O(1)`
- `O(log n)`
- `O(n)`
- `O(n log n)`
- `O(n^2)`
- `O(2^n)`

### 常见理解

- `O(1)`：常数级
- `O(log n)`：对数级
- `O(n)`：线性级
- `O(n^2)`：平方级

## 7. 空间复杂度

空间复杂度用于描述算法运行过程中额外占用存储空间的增长趋势。

例如：

- 原地交换通常空间复杂度较低
- 递归调用通常会带来额外栈空间

## 8. 最好、最坏与平均情况

分析算法性能时，常考虑：

- 最好情况
- 最坏情况
- 平均情况

课程和考试中，最常用的是最坏情况下的时间复杂度。

## 9. 常见面试问答

### 问：数据结构和数据库是一回事吗？

答：不是。数据结构更强调内存或程序中的数据组织和算法处理，数据库更强调持久化存储和查询管理。

### 问：为什么要学习复杂度分析？

答：因为复杂度可以帮助我们在不同算法之间做理性选择，而不是只看程序能不能运行。

### 问：逻辑结构和存储结构有什么区别？

答：逻辑结构描述“数据之间是什么关系”，存储结构描述“数据在计算机里怎么放”。
