# 查找结构与散列表

## 1. 查找的目标

查找问题的核心是：在给定数据集合中，快速定位目标元素或判断其是否存在。

## 2. 顺序查找

顺序查找从头到尾逐个比较。

特点：

- 实现简单
- 适用于无序表
- 时间复杂度通常为 `O(n)`

## 3. 折半查找

折半查找也称二分查找。

适用前提：

- 线性表有序
- 通常采用顺序存储

时间复杂度：

- `O(log n)`

## 4. 二叉排序树

二叉排序树支持动态查找，性质是：

- 左子树关键字小于根
- 右子树关键字大于根

若树较平衡，查找效率较高；若退化成链，效率会下降到 `O(n)`。

## 5. 平衡二叉树

平衡二叉树通过控制左右子树高度差，避免树过度退化。

常见特点：

- 查找效率稳定
- 插入和删除时可能需要旋转调整

## 6. 散列表

散列表通过散列函数把关键字映射到存储地址，实现高效查找。

核心思想：

- 直接通过关键字计算位置
- 理想情况下查找接近 `O(1)`

## 7. 冲突与处理

不同关键字可能映射到同一地址，这称为冲突。

常见冲突处理方法：

- 开放定址法
- 链地址法

## 8. 散列表设计要点

影响性能的关键包括：

- 散列函数设计
- 表长选择
- 装填因子控制

装填因子过大时，冲突通常会明显增加。

## 9. 常见考试问答

### 问：为什么二分查找不能直接用于链表？

答：因为链表不支持高效随机访问，无法像数组那样快速定位中间位置。

### 问：散列表为什么平均查找很快？

答：因为通过散列函数可以直接把关键字映射到较小范围内的位置，而不是逐个比较。

### 问：散列表一定比平衡树快吗？

答：不一定。平均情况下散列表常很快，但最坏情况可能退化；而平衡树性能更稳定，还支持有序遍历。
