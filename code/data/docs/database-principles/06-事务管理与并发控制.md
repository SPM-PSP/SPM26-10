# 事务管理与并发控制

## 1. 事务的概念
事务是数据库中的一个逻辑工作单位，要么全部执行成功，要么全部不执行。

例如转账操作通常是一个事务：
- 扣减 A 账户余额
- 增加 B 账户余额

二者必须同时成功或同时失败。

## 2. 事务的 ACID 特性
### 原子性 Atomicity
事务中的操作要么全做，要么全不做。

### 一致性 Consistency
事务执行前后，数据库必须从一个一致状态转到另一个一致状态。

### 隔离性 Isolation
并发执行的事务之间不能互相干扰。

### 持久性 Durability
事务提交后的结果应永久保存在数据库中。

## 3. 并发执行的必要性
数据库系统通常允许多个事务并发执行，以提高资源利用率和系统吞吐量。

## 4. 并发带来的问题
### 丢失修改
一个事务的更新结果被另一个事务覆盖。

### 脏读
一个事务读到了另一个未提交事务的数据。

### 不可重复读
同一事务中两次读取同一数据，结果不同。

### 幻读
同一事务中两次按条件查询，返回记录数量不同。

## 5. 封锁机制
并发控制中常见的方法是加锁。

### 共享锁 S 锁
允许读，不允许写。

### 排他锁 X 锁
允许读写者独占，不允许其他事务读写。

## 6. 两段锁协议
事务执行分为两个阶段：
- 加锁阶段
- 解锁阶段

在开始解锁后，不能再申请新锁。

两段锁协议有助于保证可串行化。

## 7. 死锁
多个事务互相等待对方释放资源而无法继续执行时，发生死锁。

应对策略：
- 预防
- 避免
- 检测与解除

## 8. 隔离级别
常见隔离级别从低到高包括：
- 读未提交
- 读已提交
- 可重复读
- 串行化

隔离级别越高，一般并发性能越低，但一致性保障更强。

## 9. MVCC
多版本并发控制通过维护数据的多个版本来提升并发读性能，广泛用于现代数据库系统。

## 10. 学习重点
- ACID 含义
- 并发异常类型
- 锁机制与两段锁协议
- 隔离级别区别
