# 数据库设计与 ER 模型

## 1. 数据库设计的目标
数据库设计的目标是在满足业务需求的前提下，构建结构合理、冗余可控、易于维护和扩展的数据组织方案。

## 2. 数据库设计的主要阶段
- 需求分析
- 概念结构设计
- 逻辑结构设计
- 物理结构设计
- 数据库实施
- 数据库运行和维护

## 3. 需求分析
需求分析需要回答：
- 系统中有哪些实体
- 实体有哪些属性
- 实体之间有什么联系
- 对数据有哪些约束
- 需要支持哪些查询和操作

## 4. ER 模型基础
ER 模型用实体、属性和联系来描述现实世界的数据结构。

### 实体
客观存在并可相互区分的事物。

### 属性
实体所具有的特征。

### 联系
实体之间的关联关系。

## 5. 联系类型
### 一对一 1:1
一个实体对应另一个实体中的一个实例。

### 一对多 1:N
一个实体可对应另一个实体中的多个实例。

### 多对多 M:N
多个实体之间相互关联，需要中间关系表表示。

## 6. ER 图示例
在教学管理系统中，常见实体包括：
- 学生
- 课程
- 教师
- 班级

其中：
- 一个教师可以教授多门课程
- 一个学生可以选多门课程
- 一个课程可被多个学生选修

学生和课程之间的多对多联系通常转化为选课表。

## 7. 逻辑结构设计
从 ER 模型转成关系模型时，一般规则是：
- 一个实体转为一张表
- 一对多联系可在“多”的一方加入外键
- 多对多联系单独转成中间表

## 8. 主键设计
主键应满足：
- 唯一
- 非空
- 稳定

主键可采用：
- 业务主键
- 代理主键

## 9. 逻辑设计中的常见问题
- 一个表承担过多含义
- 多对多关系未拆分
- 属性设计不规范
- 冗余字段过多
- 命名不一致

## 10. 物理设计考虑
物理设计涉及：
- 存储结构
- 索引设计
- 分区
- 访问路径优化

## 11. 教学建议
数据库设计题应重点训练：
- 从业务场景抽象实体和联系
- 画 ER 图
- 把 ER 图转成关系模式
- 明确主键、外键和约束
