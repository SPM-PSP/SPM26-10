# 数据库恢复技术

## 1. 为什么需要恢复
数据库系统在运行中可能遇到多种故障：
- 事务故障
- 系统故障
- 介质故障

恢复技术用于在故障后尽可能恢复数据库正确状态。

## 2. 事务故障
事务在执行过程中由于逻辑错误、输入错误或程序异常而终止，需要撤销其已执行的操作。

## 3. 系统故障
系统断电、操作系统崩溃或数据库进程崩溃等，可能导致内存中的数据丢失。

## 4. 介质故障
磁盘损坏等物理故障可能导致数据库文件损坏或丢失，后果最严重。

## 5. 恢复的基本原理
恢复通常依赖：
- 数据冗余
- 日志文件
- 检查点
- 备份副本

## 6. 日志文件
日志记录事务对数据库的更新信息。

常见记录内容：
- 事务开始
- 更新前值
- 更新后值
- 事务提交
- 事务回滚

## 7. 撤销与重做
### Undo
将未完成事务的影响撤销。

### Redo
将已提交但未写回磁盘的操作重新执行。

## 8. 检查点
检查点机制通过定期记录数据库某一时刻的状态，缩小恢复时需要扫描的日志范围。

## 9. 备份与恢复
### 静态备份
在系统停止服务时进行备份。

### 动态备份
在数据库运行过程中进行备份。

### 增量备份
只备份变化部分，节约时间和空间。

## 10. 学习重点
- 三类故障区别
- 日志的作用
- Undo 与 Redo 区别
- 检查点如何提高恢复效率
