# 索引查询优化与执行效率

## 1. 为什么需要索引
当表中数据量较大时，顺序扫描查询效率较低。索引可以帮助数据库快速定位目标记录。

## 2. 索引的本质
索引是一种辅助数据结构，用来加快查询速度。

常见索引类型：
- B+ 树索引
- 哈希索引
- 位图索引

在关系数据库教学中，B+ 树索引最常见。

## 3. 聚簇索引与非聚簇索引
### 聚簇索引
数据记录按照索引顺序组织存储。

### 非聚簇索引
索引与数据物理存储分离，索引中保存定位信息。

## 4. 哪些场景适合建索引
- 查询条件频繁出现的列
- 连接条件中的列
- 排序和分组常用列
- 唯一性要求高的列

## 5. 哪些场景不适合滥建索引
- 数据量很小的表
- 经常更新且选择性差的列
- 低区分度字段

因为索引会增加：
- 存储开销
- 插入更新删除的维护开销

## 6. SQL 查询优化的基本思路
- 减少全表扫描
- 合理使用索引
- 避免不必要的排序
- 减少返回列数
- 先过滤再连接

## 7. 常见低效写法
- `SELECT *`
- 在索引列上进行函数计算
- 模糊查询前缀使用 `%`
- 复杂子查询未改写

## 8. 执行计划
数据库可通过执行计划展示查询优化器选择的访问路径。

分析执行计划可帮助判断：
- 是否走索引
- 连接顺序
- 是否有回表
- 是否存在额外排序

## 9. 连接优化
多表连接时应注意：
- 连接条件完整
- 关联列建立索引
- 控制连接顺序和中间结果集大小

- 索引的作用与代价
- B+ 树适合数据库索引的原因
- 查询优化常见原则
