# 传输层与 TCP UDP

## 1. 传输层的作用
传输层位于网络层之上，向应用层提供端到端通信服务。

主要任务：
- 进程到进程通信
- 分段与重组
- 差错控制
- 流量控制
- 拥塞控制

## 2. 端口号
端口号用于标识主机中的应用进程。

常见端口：
- HTTP：80
- HTTPS：443
- FTP：21
- DNS：53
- SMTP：25

## 3. UDP 的特点
UDP 是无连接、不可靠的传输协议。

优点：
- 首部开销小
- 实现简单
- 时延低

适用场景：
- 语音、视频
- DNS 查询
- 实时应用

## 4. TCP 的特点
TCP 是面向连接、可靠的字节流传输协议。

主要特性：
- 建立连接
- 序号与确认
- 重传机制
- 流量控制
- 拥塞控制

## 5. TCP 三次握手
建立连接通常需要三次报文交换：

1. 客户端发送 SYN
2. 服务器返回 SYN + ACK
3. 客户端返回 ACK

作用：
- 确认双方收发能力正常
- 初始化序号

## 6. TCP 四次挥手
释放连接通常需要四次报文交换：

1. 一方发送 FIN
2. 对方回复 ACK
3. 对方发送 FIN
4. 原发送方回复 ACK

## 7. 可靠传输机制
### 序号
为每个字节或报文段编号。

### 确认
接收方通过 ACK 告知已收到的数据范围。

### 超时重传
发送方在超时未收到确认时重新发送。

### 累计确认
确认某个序号前的数据已全部收到。

## 8. 流量控制
TCP 通过接收窗口 rwnd 控制发送速度，防止接收方处理不过来。

## 9. 拥塞控制
拥塞控制的目的是避免网络中出现严重拥塞。

经典机制：
- 慢开始
- 拥塞避免
- 快重传
- 快恢复

## 10. TCP 与 UDP 对比
### TCP
- 面向连接
- 可靠
- 有序
- 适合文件传输、网页访问

### UDP
- 无连接
- 不可靠
- 开销小
- 适合实时业务

## 11. 常见题型
- 为什么 TCP 需要三次握手而不是两次
- 为什么释放连接通常是四次挥手
- TCP 可靠性由哪些机制保证
- TCP 和 UDP 适用场景比较

## 12. 学习提示
传输层是考试和面试都非常高频的部分，建议重点掌握：
- TCP 建连断连过程
- 确认与重传机制
- 流量控制与拥塞控制区别
