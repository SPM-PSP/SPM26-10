# CPU 调度算法专题

## 1. CPU 调度的任务

当系统中有多个可运行任务时，操作系统必须决定：

- 让哪个任务先运行
- 运行多长时间
- 何时切换到下一个任务

这个决策过程就是 CPU 调度。

## 2. 调度评价指标

常见评价指标包括：

- CPU 利用率
- 吞吐量
- 周转时间
- 等待时间
- 响应时间
- 公平性

不同场景关注的指标不同。

## 3. 常见调度算法

### 先来先服务 FCFS

按到达顺序执行。

优点：

- 简单

缺点：

- 长作业可能阻塞后续短作业

### 短作业优先 SJF

优先调度估计运行时间短的作业。

优点：

- 平均周转时间通常较优

缺点：

- 可能导致长作业饥饿

### 时间片轮转 RR

每个任务轮流执行一个时间片。

优点：

- 响应快
- 适合交互式系统

缺点：

- 时间片过小会带来较高切换开销

### 优先级调度

根据优先级高低决定先后。

缺点：

- 低优先级任务可能长期得不到执行

### 多级反馈队列

结合多个队列和动态优先级调整，兼顾交互性与吞吐量。

## 4. 抢占式与非抢占式

### 非抢占式

任务一旦获得 CPU，通常要等其主动让出或执行完成后才切换。

### 抢占式

操作系统可在适当时机强制暂停当前任务并切换到其他任务。

现代系统大多采用抢占式调度。

## 5. 实时调度

实时系统更关注任务是否能在规定时间内完成。

常见实时调度思路：

- 固定优先级调度
- 最早截止期限优先 EDF

## 6. 饥饿与老化

### 饥饿

某些任务长期得不到 CPU。

### 老化

随着等待时间增加逐渐提高任务优先级，以缓解饥饿问题。

## 7. 常见面试问答

### 问：为什么时间片不能设置得过小？

答：因为时间片过小会导致频繁上下文切换，增加系统开销。

### 问：SJF 为什么理论效果好但实现难？

答：因为系统通常无法准确知道一个任务未来会运行多久。

### 问：交互式系统为什么常用时间片轮转或多级反馈队列？

答：因为它们更重视响应时间，能让用户更快得到反馈。
