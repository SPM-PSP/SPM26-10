# 死锁专题

## 1. 什么是死锁

死锁是指两个或多个进程在执行过程中，因为争夺资源而造成的一种互相等待现象，导致这些进程都无法继续推进。

## 2. 死锁产生的四个必要条件

经典理论中，死锁通常需要同时满足以下四个条件：

1. 互斥
2. 占有且等待
3. 不可剥夺
4. 循环等待

只要破坏其中一个条件，就能避免死锁成立。

## 3. 死锁示例

假设：

- 进程 A 占有资源 R1，等待 R2
- 进程 B 占有资源 R2，等待 R1

此时就形成循环等待，两个进程都无法继续执行。

## 4. 死锁处理策略

常见策略包括：

- 预防
- 避免
- 检测与恢复
- 忽略

## 5. 死锁预防

死锁预防的思路是主动破坏死锁四个必要条件之一。

例如：

- 一次性申请全部资源，破坏“占有且等待”
- 资源可剥夺，破坏“不可剥夺”
- 对资源编号并按顺序申请，破坏“循环等待”

## 6. 死锁避免

死锁避免是在资源分配时动态判断当前分配是否会进入不安全状态。

经典算法：

- 银行家算法

核心思想是：

- 只有在分配后系统仍然安全时，才允许分配资源

## 7. 死锁检测与恢复

如果系统允许死锁发生，就需要：

1. 周期性检测死锁
2. 发现死锁后采取恢复措施

恢复措施可能包括：

- 撤销部分进程
- 回滚到先前状态
- 强制回收资源

## 8. 忽略策略

某些通用操作系统对死锁采取“鸵鸟策略”，即默认认为死锁概率较低，不专门处理，由应用或管理员解决。

## 9. 常见面试问答

### 问：死锁和饥饿有什么区别？

答：死锁是相互等待且都无法继续；饥饿是某个任务长期得不到资源，但系统其他部分仍可能继续运行。

### 问：为什么按固定顺序申请资源能减少死锁？

答：因为这样可以破坏循环等待条件。

### 问：银行家算法的核心思想是什么？

答：只在资源分配后系统仍处于安全状态时才允许分配。
