# 内存管理与地址空间

## 1. 内存管理的目标

操作系统中的内存管理主要解决以下问题：

- 如何给进程分配内存
- 如何回收内存
- 如何避免不同进程互相覆盖数据
- 如何提高内存利用率
- 如何支持程序只看到连续的逻辑地址空间

## 2. 地址空间的概念

每个进程通常都认为自己独占整个内存空间，这个“进程视角下的内存”称为地址空间。

地址空间一般包括：

- 代码段
- 数据段
- 堆
- 栈
- 动态链接库映射区

不同进程的地址空间彼此隔离，这是操作系统提供内存保护的重要基础。

## 3. 逻辑地址与物理地址

### 逻辑地址

程序中使用的地址，也称虚拟地址。

### 物理地址

真实的硬件内存地址。

操作系统和硬件中的地址转换机制负责把逻辑地址映射成物理地址。

## 4. 连续分配与碎片问题

早期内存管理常采用连续分配，即每个进程占据一段连续物理内存。

常见问题：

- 外部碎片：空闲内存很多，但不连续，导致无法满足大块分配
- 内部碎片：分配块大于实际需求，造成块内浪费

## 5. 分页机制

分页把逻辑地址空间和物理内存划分为固定大小的页和页框。

优点：

- 避免外部碎片
- 便于离散分配
- 容易和虚拟内存机制结合

页表用于记录逻辑页号到物理页框号的映射关系。

## 6. 分段机制

分段按程序逻辑结构划分，例如：

- 代码段
- 数据段
- 栈段

优点：

- 更贴近程序逻辑组织

缺点：

- 仍可能产生外部碎片

## 7. 分页与分段对比

### 分页

- 固定大小
- 更利于实现和管理
- 对程序员不透明

### 分段

- 大小不固定
- 更符合程序逻辑
- 保护和共享表达更自然

实际系统中也可能结合使用。

## 8. 内存保护

操作系统通过内存保护机制防止：

- 一个进程访问另一个进程内存
- 用户程序随意访问内核地址
- 越界写破坏系统稳定性

## 9. 常见面试问答

### 问：为什么进程需要独立地址空间？

答：为了隔离故障和保护数据，避免一个进程误修改另一个进程的内存内容。

### 问：分页为什么能减少外部碎片？

答：因为分页允许进程占用多个离散页框，不要求物理内存连续。

### 问：逻辑地址一定比物理地址大吗？

答：不一定，它们是不同层面的地址表示，关键在于是否经过映射转换。
