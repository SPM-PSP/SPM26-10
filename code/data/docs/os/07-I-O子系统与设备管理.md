# I/O 子系统与设备管理

## 1. I/O 子系统的作用

I/O 子系统负责管理操作系统与外设之间的数据交换，是连接 CPU、内存与各种设备的重要桥梁。

设备类型多样，包括：

- 键盘、鼠标
- 显示器
- 磁盘
- 网卡
- 串口设备
- 传感器与控制器

## 2. 设备管理的目标

设备管理需要解决：

- 设备分配与释放
- 设备访问控制
- 设备驱动适配
- 数据传输效率
- 错误检测与恢复

## 3. 设备控制方式

常见设备控制方式包括：

### 程序控制 I/O

CPU 直接轮询设备状态，效率较低。

### 中断驱动 I/O

设备在准备好数据或完成操作后通知 CPU。

### DMA

设备可在 DMA 控制器协助下直接与内存交换数据，减少 CPU 参与。

## 4. DMA 的作用

DMA 适合大块数据传输，例如磁盘、网卡、音视频数据。

优点：

- 减少 CPU 负担
- 提高数据传输效率

## 5. 设备独立性

操作系统希望应用层尽量不关心底层设备差异，因此通常会通过统一接口隐藏具体硬件细节。

例如：

- 文件接口
- 块设备接口
- 网络套接字接口

## 6. 设备驱动在 I/O 子系统中的位置

驱动是 I/O 子系统中与具体设备最贴近的一层。

它把：

- 上层的统一请求

转换成：

- 对具体硬件寄存器、中断和传输方式的操作

## 7. 常见面试问答

### 问：为什么 DMA 能提高效率？

答：因为它减少了 CPU 在数据搬运上的参与，让 CPU 可以并行处理其他工作。

### 问：程序控制 I/O 为什么效率低？

答：因为 CPU 要不断轮询设备状态，浪费大量时间等待。

### 问：设备独立性为什么重要？

答：因为它降低了应用程序对具体硬件差异的依赖，提高了系统可移植性。
